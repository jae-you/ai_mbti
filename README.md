# 나한테 맞는 AI 에이전트는? — 위임 성향 연구

AI 에이전트에게 어디까지 맡기고 어디서부터 사람이 해야 하는지를 찾는 온라인 실험입니다.
참가자는 16개 상황을 판단하고(1단계), 그중 3가지를 에이전트가 실제로 처리한 결과를
두 가지 버전으로 비교합니다(2단계). 끝나면 위임 성향 유형이 나옵니다.

## 구성

```
index.html                 # 실험 앱 (정적 페이지, GitHub Pages로 배포)
stimuli.js                 # 고정 자극 32개 (16 시나리오 × 2 요인 × 2 버전)
apps-script/Code.gs        # 백엔드: 응답 저장
analysis/simulate_power.py # 가상 데이터로 분석 모형과 검정력 확인
```

## 1. 스프레드시트와 백엔드 만들기

1. 구글 스프레드시트를 새로 만든다.
2. **확장 프로그램 → Apps Script**를 열고 `apps-script/Code.gs` 내용을 붙여넣는다.
3. **프로젝트 설정 → 스크립트 속성**에 추가한다.
   - `SHARED_TOKEN` : 아무 문자열 (예: `jy-2026-delegation`). API 키는 필요 없다.
   - (선택) `COLLECTING` : 수집을 멈추고 싶을 때 `off`로 바꾸면 더 이상 저장되지 않는다.
4. **배포 → 새 배포 → 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 후 나오는 `https://script.google.com/macros/s/..../exec` 주소를 복사한다.
5. 스프레드시트를 새로고침하면 상단에 **연구** 메뉴가 생긴다 (분석용 정리에 쓴다).

## 2. 앱 설정하고 배포하기

`index.html` 상단 `CONFIG`를 채운다.

```js
const CONFIG = {
  endpoint: "https://script.google.com/macros/s/..../exec",
  token: "jy-2026-delegation",
  gameCount: 3,
  irbText: "연구책임자 유재연 · 문의 sandrine86@hanyang.ac.kr",
  shareUrl: "https://<아이디>.github.io/<저장소>/"   // 배포 주소
};
```

GitHub 저장소에 올리고 **Settings → Pages → Branch: main / root**로 배포한다.
모집 경로를 나눠 보려면 `?src=twitter` 처럼 붙이면 `src` 열에 기록된다.
패널을 쓸 경우 `?pid=...`로 참가자 식별자를 넘길 수 있다.

## 3. 데이터 보기

- `raw` 시트에 세션 JSON이 그대로 쌓인다 (단계가 끝날 때마다 1행, 중도 이탈도 남는다).
- **연구 → 분석용 시트로 정리**를 누르면 세 시트가 만들어진다.
  - `responses` : 1단계 판단 1행 = 사람 × 상황
  - `comparisons` : 2단계 비교 1행 = 사람 × 상황
  - `sessions` : 사람 1행 (성향 문항, 유형, 선택 분포 포함)
- 분석은 `responses`를 CSV로 내려받아 쓰면 된다.

## 4. 분석 계획 (사전등록용 요약)

- **주 가설** : 선례가 되는 상황에서, 사전에 위임을 택한 사람의 사후 거부 비율이
  평범한 조율 상황보다 높다.
- 모형 1 : 순서형 로지스틱 (종속=그냥 맡김/선 긋고 맡김/직접, 예측=선례성·표명성·가역성·관계),
  참가자와 시나리오에 랜덤 절편.
- 모형 2 : 사후 거부 여부에 대한 로지스틱, 사전 선택 × 상황 유형 상호작용.
- 모형 3 : 2단계 선택(hold/yield, closed/open)에 대한 로지스틱, 관계 성향과의 상호작용.
- 검정력 : `analysis/simulate_power.py` 참고. 가정한 효과 크기에서 N=80이면 95%.

## 위임 정책 추출

참가자의 1단계 응답을 네 가지 작업군(표명 / 선례 / 경계 / 조율)으로 묶어
각 군의 최빈 선택을 규칙으로 뽑습니다. 설문 뒤에 그 규칙을 보여주고
참가자가 줄마다 승인하거나 고치게 합니다. 승인 비율이 모델 정확도이고,
고친 내용은 `policy.rules[].corrected`에 남습니다.
결과 화면에서는 에이전트에 주입할 수 있는 JSON으로 내려받을 수 있습니다.

## 자극에 대하여

2단계에서 참가자가 보는 에이전트 협상문은 `stimuli.js`에 고정되어 있습니다.
실시간 생성이 아니라 연구자가 작성한 통제 자극이며, 두 버전은 조작 요인
(양보 권한 / 마무리 방식) 외에 길이·어조·합의 내용을 맞췄습니다.
모든 참가자가 동일한 자극을 보므로 조건 간 비교가 깨끗하고, 자극 전문을
논문 부록에 그대로 실을 수 있습니다.

## 보안에 대하여

- 저장소는 **public**이어야 합니다. private 저장소는 무료 플랜에서 GitHub Pages 배포가
  되지 않고, 유료 플랜에서도 방문자에게 GitHub 로그인을 요구해 모집 링크로 쓸 수 없습니다.
- 브라우저에서 실행되는 코드는 어차피 모두 공개됩니다. 그래서 이 저장소에는
  **비밀로 지켜야 하는 값을 두지 않습니다.** (LLM API 키 없음)
- `CONFIG.token`은 비밀이 아니라 자동 요청을 거르는 필터입니다. 토큰이 알려져도
  가능한 일은 가짜 응답을 보내는 것뿐이며, 시트를 읽거나 기존 데이터를 지울 수는 없습니다.
  백엔드에 세션당 행 수 제한, 크기 제한, 전체 행 수 상한, 수집 종료 스위치를 두었습니다.
- 스프레드시트 자체는 아무에게도 공유하지 마세요. 응답은 그 안에만 쌓입니다.
- 수집이 끝나면 스크립트 속성 `COLLECTING`을 `off`로 바꾸거나 웹앱 배포를 해제하세요.

## 윤리

이름·연락처는 수집하지 않습니다. 상대 에이전트 대화는 연구용으로 생성된 것이며
실제 상대와 주고받은 대화가 아닙니다. 참가자에게 종료 화면에서 이를 밝힙니다.
